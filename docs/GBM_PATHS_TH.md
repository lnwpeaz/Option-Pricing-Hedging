# จากราคาปลายปี สู่เส้นทางหุ้นตลอดปี

Milestone 3 ทำแล้ว: สร้างข้อมูลราคาหุ้นระหว่างทาง เพื่อเตรียมทดลอง Delta Hedging
ยังไม่มีการซื้อขายหุ้นหรือบัญชี hedge ในผลรอบนี้

## เราเพิ่มอะไรจาก Monte Carlo เดิม

ก่อนหน้านี้เราประมาณราคา Call/Put โดยสุ่มราคาหุ้นที่วันหมดอายุ แล้วเฉลี่ย payoff
ตอนนี้เราสุ่มราคาหุ้นหลายจุดตลอดอายุสัญญา เก็บทั้งขึ้น ลง และกลับทิศ
เพื่อให้ขั้นถัดไปตอบได้ว่า “ในแต่ละวันควรปรับหุ้นเท่าไร”

Monte Carlo เป็นวิธีใช้การสุ่มจำนวนมากเพื่อประมาณผล ส่วน GBM หรือ Geometric
Brownian Motion เป็นแบบจำลองที่กำหนดว่าหุ้นเคลื่อนไหวอย่างไร เราใช้ทั้งสองอย่างร่วมกัน
GBM ที่เลือกเป็นสมมติฐานสำหรับห้องทดลอง ไม่ใช่โมเดลที่ฝึกจากข้อมูลตลาดจริง

ข้อมูลหนึ่งแถวคือโลกจำลองหนึ่งใบ แต่ละคอลัมน์คือเวลาหนึ่งจุด:

```text
                   วันนี้   จุดถัดไป   ...   ครบสัญญา
โลกจำลอง path 0       100       ...     ...      ...
โลกจำลอง path 1       100       ...     ...      ...
...
โลกจำลอง path 9999    100       ...     ...      ...
```

ตัวอย่างจริงอยู่ใน reports/examples/milestone-3/paths.png และ paths.npy
ทุกเส้นเริ่มที่ 100 เหมือนกัน แต่มีการเปลี่ยนแปลงระหว่างทางต่างกัน

## ค่าที่ใช้สร้างโลกจำลอง

configs/gbm_paths.toml กำหนดค่าตั้งต้นไว้ชัดเจน:

| ค่า | ตัวอย่างนี้ | ความหมาย |
|---|---:|---|
| spot | 100 | ราคาหุ้นเริ่มต้น |
| maturity_years | 1 | จำลองหนึ่งปี |
| physical_drift | 0.08 | drift ต่อปีแบบต่อเนื่องที่สมมติสำหรับตลาด |
| risk_free_rate | 0.05 | ดอกเบี้ยต่อปีแบบต่อเนื่อง สำหรับตรวจการตั้งราคา |
| volatility | 0.20 | ระดับความผันผวนรายปีที่สมมติ |
| paths | 10000 | จำนวนโลกจำลอง |
| steps_per_year | 252 | ความถี่ของกริดเวลาแบบจำลอง |
| seed | 421021 | ค่าตั้งต้นสำหรับทำซ้ำการสุ่ม |

Drift 8% ในสูตรต่อเนื่องหมายถึงค่าเฉลี่ยปลายปีตามทฤษฎี 100*exp(.08)=108.3287
ไม่ได้หมายความว่าทุกเส้นจะโต 8% และไม่ได้เป็นการพยากรณ์ว่าหุ้นจริงจะขึ้นเท่านั้น
Volatility ทำให้เส้นทางกระจายรอบแนวโน้ม หลายเส้นอาจลงแม้ drift เป็นบวก

## สูตรการเปลี่ยนราคาหนึ่งช่วง

```text
S_next = S_now * exp((drift - sigma²/2)*dt + sigma*sqrt(dt)*Z)
Z ~ N(0,1)
```

dt คือระยะเวลาของช่วงนั้นในหน่วยปี เช่น 1/252 ส่วน Z เป็นความสุ่มใหม่ในแต่ละช่วง
สูตรนี้เป็น exact transition ของ GBM ที่มีพารามิเตอร์คงที่ ณ จุดเวลาที่กำหนด
เราไม่ได้ใช้ Euler approximation จึงไม่มี time-step bias แบบ Euler ที่จุดกริด
แต่ยังมี sampling error, floating-point error และข้อจำกัดจากตัวแบบ
เราไม่ได้จำลองรายละเอียดระหว่างจุดกริดอย่างต่อเนื่อง

ถ้า sigma=0 ทุกเส้นจะเหมือนกันและเคลื่อนตาม S0*exp(drift*t) โดยไม่ใช้ RNG
ถ้ากริดมีเพียง [0] จะได้ราคาเริ่มต้นอย่างเดียว ฟังก์ชันยังตรวจ input ให้ถูกต้องก่อนเสมอ

## ทำไมมีทั้ง Physical และ Risk-neutral

**Physical** ใช้ drift mu เพื่อสร้างสถานการณ์ตลาดสำหรับทดลองความเสี่ยง
**Risk-neutral** ใช้ drift r เพื่อตรวจความสัมพันธ์ในการตั้งราคา
ตัว core รับ drift ตรง ๆ ไม่เดาว่าต้องใช้ measure ใดจากบริบท

ใน demo เราให้สองชุดใช้ความสุ่มเดียวกัน เพื่อแยกผลของการเปลี่ยน drift ออกจาก noise:

```text
S_physical(t) / S_risk_neutral(t) = exp((mu-r)*t)
```

ทั้งสองชุดจึงเป็นคู่เปรียบเทียบ ไม่ใช่หลักฐานอิสระสองชุด
ไฟล์ paths.npy ที่จะส่งต่อให้ระบบ hedge เก็บเฉพาะชุด Physical
ชุด RN ใช้ทำกราฟและตรวจแบบจำลอง โดยเก็บราคาปลายทางและสถิติไว้ด้วย

## อ่านผลที่รันจริง

ตัวอย่างหลักสร้าง 10,000 เส้นทาง × 253 จุดเวลา มี 252 ช่วงตลอดหนึ่งปี
paths.png แสดง 12 path IDs แรก ไม่มีการเลือกเส้นที่ดูสวยหรือให้ผลดี
ด้านล่างเป็นสถิติจากทั้ง 10,000 เส้นทาง:

- แถบ 5th–95th percentile: การกระจายของราคาข้าม paths ณ แต่ละเวลา
- เส้น median: ราคาตรงกลางของตัวอย่างทั้งหมด
- เส้น mean: ราคาเฉลี่ยของตัวอย่างทั้งหมด
- เส้น theoretical mean: ค่าเฉลี่ยที่สูตร GBM บอกว่าควรเป็นในประชากร

**แถบ percentile ไม่ใช่ช่วงความเชื่อมั่นของค่าเฉลี่ย** และยังไม่ใช่ forecast interval
ที่ตรวจสอบกับราคาตลาดจริงแล้ว Mean และ median ต่างกันได้เพราะราคามีการกระจายเอียง

ผล baseline:

| รายการ | ผลจำลอง | ค่าทฤษฎี |
|---|---:|---:|
| ราคาเฉลี่ย Physical ปลายปี ในชุดหลัก | 107.9385 | 108.3287 |
| ราคาเฉลี่ย RN ปลายปี ในชุดหลัก | 104.7485 | 105.1271 |
| ราคาเฉลี่ย RN หลังคิดลด ในชุดหลัก | 99.6398 | 100 |
| ราคาเฉลี่ย RN หลังคิดลด ข้าม 32 repeats | 100.0094 | 100 |

ชุดหลักมี sampling error จึงไม่ต้องตรงทฤษฎีเป๊ะ การตรวจซ้ำแยก 32 ชุด ชุดละ
2,000 paths ช่วยประเมินความไม่แน่นอนของค่าเฉลี่ยโดยไม่ตัดสินจาก seed เดียว
ช่วงประมาณ 95% ของ RN discounted ensemble mean อยู่ราว [99.8591, 100.1597]
ทั้งหมดเก็บไว้ใน validation.csv และ summary.json รวมทั้งผล log-return mean/variance
ซึ่งตามทฤษฎีเป็น (drift-sigma²/2)*T และ sigma²*T ตามลำดับ

## กริดเวลาที่ระบบ hedge จะใช้

make_time_grid สร้าง 0, จุด k/steps_per_year ที่ยังไม่ถึงวันหมดอายุ และวันหมดอายุจริง
ถ้าอายุสัญญาไม่ลงตัวกับกริด ช่วงสุดท้ายจะสั้นกว่า ตัวอย่าง T=.6 และความถี่ 4:

```text
[0, .25, .50, .60]   →   dt = [.25, .25, .10]
```

simulate_paths รองรับกริดไม่สม่ำเสมออยู่แล้ว ใช้ dt และ sqrt(dt) ของแต่ละช่วงจริง
คุณสมบัตินี้สำคัญต่อการคิดดอกเบี้ยและตัดสินใจ hedge ในขั้นถัดไป
คำว่า daily/weekly ในโปรเจกต์หมายถึงทุก 1/5 จุดบนกริด ไม่ใช่ปฏิทินวันหยุดตลาดจริง

## จุดเชื่อมกับ Computer Engineering

ตัวจำลองใช้ array operations แทน loop คำนวณทีละหุ้น แล้วแบ่งงานเป็น batch ตาม path
นำ array ชั่วคราวเดิมกลับมาใช้กับ normal draws, log increments, cumulative sums และ exp

- เวลาคำนวณ O(N*M): N paths และ M ช่วงเวลา
- ข้อมูลที่ส่งคืน O(N*M): ต้องเก็บทุกจุดเพื่อให้ hedge อ่านระหว่างทางได้
- พื้นที่ทำงานชั่วคราว O(B*M): B คือ batch size
- เมทริกซ์ Physical baseline ใช้ข้อมูล 20,240,000 bytes หรือประมาณ 19.30 MiB
- buffer float64 ที่ batch=512 ใช้ประมาณ 0.984 MiB; ไม่รวม boolean masks และงานวิเคราะห์
- Demo ถือ RN matrix เพิ่มด้วย จึงมีข้อมูล matrix สองชุดประมาณ 38.60 MiB

ตัวเลขขนาด array เหล่านี้ไม่ใช่ process RAM สูงสุดทั้งหมด และเวลารันครั้งเดียวในรายงาน
เป็นข้อมูลประกอบ ไม่ใช่ benchmark ที่ควรนำไปอ้าง speedup
การสรุป SD/SE ใช้การปรับสเกลและ central moments เพื่อไม่ยกกำลังสองเงินจำนวน
เล็กหรือใหญ่มากโดยตรง มี hand-worked tests สำหรับสเกล 1e-170 และ 1e150 ด้วย

โฟลเดอร์ผลลัพธ์ต้องเป็นโฟลเดอร์ใหม่เพื่อรักษาผลเก่าไว้

```python
import numpy as np

                       times=times, n_paths=10_000,
                       rng=np.random.Generator(np.random.PCG64(42)), batch_size=512)

# หรืออ่านชุดที่รันไว้ เพื่อให้หลายวิธี hedge ใช้โลกจำลองเดียวกัน
paths = np.load("reports/examples/milestone-3/paths.npy", allow_pickle=False)
```

Seed keys ของชุดหลักคือ [3,0,seed] และ validation คือ [3,1,repeat_id,seed]
แต่ละ measure เริ่ม Generator ด้วย key เดียวกันภายในคู่ ทำให้ใช้ Brownian shocks เดียวกัน
ไฟล์ manifest เก็บรูปแบบการเรียก RNG, config, package versions, source/output hashes
การทำซ้ำอยู่ภายใต้ environment ที่บันทึกไว้ ไม่รับรอง bitstream ทุกเวอร์ชัน NumPy
หรือทุกรูปแบบการเรียก RNG

## เราจะนำไปทำอะไรต่อ

ขั้นถัดไปคือบัญชี self-financing hedge สำหรับผู้ขาย Call:
รับ premium → ซื้อหุ้นตาม Delta → เก็บเงินสด/ยอดกู้ → คิดดอกเบี้ย → ปรับหุ้นและจ่ายค่าซื้อขาย
→ จบสัญญาขายหุ้นคงเหลือและจ่าย payoff

เมื่อบัญชีนี้ตรวจถูกต้องแล้ว จะเปรียบเทียบ hedge ทุกวันกับทุกสัปดาห์บน path IDs เดียวกัน
จึงวัดได้ว่าความเสี่ยงและต้นทุนต่างกันเพราะวิธี hedge ไม่ใช่เพราะบังเอิญสุ่มได้ตลาดคนละชุด
ตอนนี้เรามี “โลกจำลอง” พร้อมแล้ว ส่วนการทดลองบริหารเงินภายในโลกเหล่านั้นเป็นงานถัดไป
